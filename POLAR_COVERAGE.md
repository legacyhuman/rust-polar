# Polar AccessLink coverage

Status snapshot against [`SPEC.md` §5](SPEC.md) and the source currently in
`src/polar/`, `src/ingest.rs`, `src/main.rs`, and `src/storage.rs`. This is implementation
coverage, not a claim that every endpoint is available to Polar Loop.

`implemented` means the named layer exists for the stated scope; `partial`
means part exists but a listed requirement is missing; `archive-only` means
the generic raw archive can retain a response, without a resource-specific
decoder/query path; `missing` means no resource-specific implementation was
found. The generic record page is not a normalized time-series query.

## Cross-resource behavior

- `polar::sync` runs the request plan, archives each response before replay, follows pagination only on the AccessLink HTTPS origin, and records pending/processed/no-data/error state. Initial activity backfill uses documented 28-day request windows; later cycles reread recent days. Endpoint-specific limits and live response variants still need review.
- The scheduler runs inside `serve` every 30 minutes by default. `sync polar [--from --to]` runs once; its admin socket route shares a mutex with the scheduler cycle. Explicit ranges are inclusive and limited to 365 days for activity history.
- Network retries cover timeouts, 429, and 5xx. Retry-After supports delta seconds and HTTP dates. HTTP 401 and 403 are surfaced distinctly. Local loopback HTTP and Unix-socket tests exercise the shared streaming archive path, chunked bodies, response headers, interrupted bodies, cancellation, and archive-admin verify/diagnose/cleanup routes including dry-run, malformed requests, and sync-lock conflicts; the production connector remains HTTPS-only.
- Replay persists parsed provider records and their fields in redb, then inserts UTC-resolved normalized measurements in bounded idempotent batches. Provider-local/unresolved times remain available in records and are excluded from UTC series results.
- Source response archives remain on disk for integrity checks and crash recovery. Intermediate JSON files are not needed; parsed records and queryable measurements are the durable application data, while FIT/TCX/GPX remain compressed archive objects addressable through indexed records.
- Archived binary exercise exports are available through the private local API as bounded-memory streams. Tests cover missing/corrupt objects, client disconnect, source-body interruption, archive ENOSPC/fsync/rename faults, and archive-admin verification/diagnosis/cleanup.
- `/v1/series` supports bounded chart downsampling with actual first/min/max/last source measurements; no synthetic values are written to redb.

records a 2026-10-21 check and notes that HTML documentation and published
Swagger differ, particularly for current non-transactional endpoints. Confirm

hashed string IDs in examples, snake_case top-level keys, and comma-separated
string `samples[].data`; the archived response remains authoritative.
